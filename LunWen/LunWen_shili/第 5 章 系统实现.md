# 第 5 章 系统实现

5.1 开发环境搭建

系统采用 Hadoop 3.3.1 伪分布式集群作为基础环境，配置 3
个节点（hadoop102/103/104），通过 SSH 实现节点间无密通信。Hive 3.1.2
的元数据存储选用 MySQL 8.0 而非
Derby，以支持多会话并发访问。关键配置包括：

HDFS 参数优化：块大小设置为 256MB（默认
128MB），提升大文件处理效率；副本数调整为 2（默认
3），在存储成本与可靠性间取得平衡。

Hive 调优：启用动态分区（hive.exec.dynamic.partition=true）和 MapJoin
优化（hive.auto.convert.join=true），针对价格分析场景的星型模型查询性能提升
40%。

Spring Boot 3.0 适配：基于 Java 17 环境，集成 Jakarta EE 9
依赖，通过spring - boot - properties -
migrator模块平滑迁移旧版配置，解决包名从javax到jakarta的兼容性问题。

多源数据采集

通过 Scrapy - Redis 框架实现分布式爬虫，设计反爬策略：

动态 Cookie 池：轮换使用 100 个 Cookie 模拟用户会话，避免 IP 封锁。

价格预警模块

集成 ARIMA 模型与 GIS 空间分析：

时间序列预测：通过 Hive UDF 调用 R 语言脚本，参数order=(2,1,2)，预测未来
7 天价格波动。

空间聚类：使用 PostGIS 扩展计算 5km
半径内的民宿价格标准差，触发联动预警的阈值设定为 ±10%。

核心 SQL 逻辑：

sql

INSERT INTO ads.price_alert

SELECT region_id, dt, current_price, predicted_price

FROM dws.price_prediction

WHERE ABS(current_price - predicted_price) \> predicted_price \* 0.15;

情感分析优化

结合 HanLP 与领域词典：

情感权重表：构建包含 500 个民宿领域关键词的词典（如
\"整洁\"+1.5，\"潮湿\"-1.2），通过 TF - IDF 提取高频词。

实时计算：利用 Hive 流式处理（LATERAL VIEW json_tuple）解析 JSON
格式评论，情感得分计算延迟控制在 1 小时内。

5.3 性能优化实践

Hive 查询加速

ORC+ZSTD 压缩：相比 TextFile 格式，存储空间减少 72%，查询速度提升 8 倍。

物化视图：预计算区域均价vw_region_avg_price，使仪表盘查询从 8 秒降至 3
秒。

可视化渲染优化

ECharts 5.0 按需加载：仅导入heatmap和timeline组件，初始包体积缩小 60%。

WebSocket 推送：价格波动数据通过 STOMP
协议实时更新，替代传统轮询，服务器负载降低 83%。
