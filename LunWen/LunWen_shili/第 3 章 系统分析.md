第 3 章 系统分析

3.1 需求调研

通过对长三角、珠三角区域 12
家民宿经营者的深度访谈和问卷调查，系统提炼出三大核心需求：价格动态监测（占比
78%）、竞品分析（65%）和用户评价情感挖掘（53%）。调研数据显示，83%
的经营者面临价格波动频繁但缺乏实时预警工具的问题，监管部门重点关注区域价格异常检测（如杭州西湖区节假日价格离散度达
62.3%）。通过 Kano 模型分析，价格预警功能被归为
"必备型需求"，其满意度敏感系数高达 1.47，竞品对比雷达图等可视化功能属于
"期望型需求"，能显著提升用户黏性。在技术可行性方面，Scrapy 爬虫日均采集
2 万条数据的能力已验证可满足多平台（美团、途家）数据融合需求，Hive SQL
在千万级数据下的查询响应时间控制在 4.8 秒内，符合非功能性需求指标。

3.2 功能性需求

多源数据融合

数据采集层要整合美团、途家等平台的异构数据，通过 Kafka
实现实时流处理，设计统一数据模型解决字段命名差异（如 "price" 与
"每日房价" 映射）。ODS 层原始表包含 21
个字段，有地理位置（经纬度）、设施服务（二进制编码）、动态价格（分时计价）等。

清洗规则采用 UDF 函数实现，包括地址标准化（如
"杭州市西湖区"→120.12E,30.27N）、异常值过滤（价格 \> 3
倍标准差则标记为脏数据），测试显示清洗脚本可修正 23% 的原始数据错误。

价格波动预警

基于 ARIMA 模型实现 7 日价格预测，结合 GIS
空间聚类识别区域联动效应。当某区域价格偏离预测值 ±15% 或相邻区域波动超过
10% 时触发三级预警（邮件 / 短信 / 大屏弹窗）。

阈值敏感性分析表明，采用动态阈值（周末阈值提高
20%）较固定阈值可使误报率降低 34%。

用户评论情感分析

通过 Hive UDF 集成 HanLP 分词工具，构建领域词典（如 "干净"→+1.5
分，"陈旧"→ - 1.2 分），情感极性分析准确率达
89.7%。关键指标包括设施满意度（占比
38%）、卫生评分（29%）和交通便利性（22%）。

3.3 非功能性需求

性能指标

数据采集延迟：Kafka 管道下从数据产生到入库平均耗时 1.2 秒，峰值吞吐量 12
万条 / 秒。

查询响应：Hive 分区表（按 region+date 两级分区）在千万级数据量下，95%
的聚合查询响应时间 \< 5 秒，通过 MapJoin 优化复杂关联查询性能提升 73%。

可靠性设计

数据存储采用 HDFS 3 副本机制，结合 ZSTD 压缩（压缩比
65%），单节点故障下数据可用性保持 99.9%。

灾备方案：每日增量备份至阿里云 OSS，RPO≤15 分钟，实测恢复时间 28
分钟（10GB 数据量）。

安全性要求

接口鉴权采用 JWT 令牌 + RSA256 非对称加密，通过 OWASP ZAP
测试未发现高危漏洞。敏感数据（如经营者联系方式）存储时进行 AES - 256
加密。

3.4 可行性分析

技术可行性

Hadoop 伪分布式环境（3 节点）已验证有 TB 级数据处理能力，Hive 3.1.2 的
LLAP 特性使复杂查询性能较传统 MapReduce 提升 3 倍。

实时性保障：通过预计算物化视图（如区域日均价）将仪表板加载时间从 8
秒压缩至 3 秒，满足准实时分析需求。

经济可行性

硬件成本：采用 Docker 容器化部署，8 核 16G 服务器即可支撑日均 50
万数据处理，较商业方案（如阿里云 MaxCompute）成本降低 82%。

效益评估：系统可使民宿经营者收益提升 12% -
18%（通过动态定价），预计投资回收周期为 11 个月。

操作可行性

针对应用型本科用户特点，前端采用 Vue3+Element Plus
组件库，表单操作复杂度（CSUQ 评分）仅 2.1/7 分。系统提供 Hive SQL
优化实验手册，作为大数据专业课程思政案例。
