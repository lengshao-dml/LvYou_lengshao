# 第 5 章 系统实现

## 5.1 开发环境搭建

本旅游城市推荐系统在以下开发环境下进行搭建和部署：

- **操作系统：** Arch Linux (或兼容的 Linux 发行版，如 CentOS、Ubuntu)。
- **后端开发环境：**
  - **Java Development Kit (JDK)：** OpenJDK 17.0.16 (或更高版本)。
  - **构建工具：** Apache Maven 3.9.11 (或更高版本)。
  - **Web 框架：** Spring Boot 3.2.x。
  - **数据库：** MariaDB 12.0.2 (或 MySQL 8.0.x 兼容版本)。
  - **缓存服务：** Valkey 8.1.3 (或 Redis 兼容版本)。
- **前端开发环境：**
  - **Node.js：** 20.x (或 LTS 版本)。
  - **包管理工具：** npm (与 Node.js 捆绑)。
  - **JavaScript 框架：** Vue 3.x。
  - **UI 组件库：** Bootstrap 5.x。
- **容器化：** Docker 28.x (用于本地开发和生产环境部署)。

**关键配置与适配：** \* **数据库连接：** Spring Boot 配置文件
`application.properties` 中配置 MariaDB
连接信息，包括驱动、URL、用户名和密码。使用
`spring-boot-starter-data-jpa` 整合 Hibernate ORM。 \* **缓存集成：**
引入 `spring-boot-starter-data-redis` 依赖，配置 Valkey 连接，并使用
Spring 的 `@Cacheable` 等注解实现缓存功能。 \* **Spring Boot 3.x
适配：** 鉴于 Spring Boot 3.x 升级到 Jakarta EE 9，确保所有 `javax.*`
包引用更新为 `jakarta.*`，或通过 `spring-boot-properties-migrator`
模块辅助平滑迁移，确保兼容性。

## 5.2 关键功能实现

### 5.2.1 用户偏好收集与管理

- **前端实现：**
  - 在 Vue 3 界面中，通过 `el-select` 组件（假设使用 Element Plus UI
    库）实现出发地选择。
  - 兴趣标签通过 `el-checkbox-group` 或自定义标签选择组件实现多选功能。
  - 计划出行日期使用 `el-date-picker` 组件进行选择。
  - 用户提交偏好后，通过 Axios 发送 POST 请求至后端 API。
- **后端实现：**
  - `UserController` 接收用户偏好提交，调用 `UserService` 处理业务逻辑。
  - `UserService`
    将偏好数据（用户ID、兴趣标签ID列表、出发城市ID、出行日期）持久化到
    MariaDB 的 `user` 和 `user_interest_tag` 表中。
  - 使用 Spring Data JPA 的 `UserRepository` 和
    `UserInterestTagRepository` 进行数据库操作。

**代码示例 (UserInterestService.java):**

``` java
@Service
public class UserInterestService {

    @Autowired
    private UserInterestTagRepository userInterestTagRepository;
    @Autowired
    private TagRepository tagRepository;
    @Autowired
    private CityRepository cityRepository;

    @Transactional
    public void updateUserPreferences(Long userId, List<String> interestTagNames, String departureCityName, LocalDate travelDate) {
        // 更新用户兴趣标签
        userInterestTagRepository.deleteByUserId(userId); // 清除旧标签
        List<Tag> tags = tagRepository.findByNameIn(interestTagNames);
        tags.forEach(tag -> {
            UserInterestTag userInterestTag = new UserInterestTag();
            userInterestTag.setUserId(userId);
            userInterestTag.setTagId(tag.getId());
            userInterestTagRepository.save(userInterestTag);
        });

        // 更新用户出发城市 (示例，实际可能在User表中更新)
        cityRepository.findByName(departureCityName).ifPresent(city -> {
            // Logic to update user's departure city in User entity
            // For simplicity, this might be handled in UserService
        });

        // 记录出行日期 (示例，实际可能在RecommendationRequestDto中临时使用)
    }
}
```

### 5.2.2 核心推荐引擎服务

- **后端实现：**
  - `RecommendationController` 接收用户推荐请求，调用
    `RecommendationService`。
  - `RecommendationService` 负责协调各子模块，执行推荐算法。
  - **数据获取：** 从 MariaDB 获取城市特征标签、城市地理位置。从 Valkey
    缓存或第三方 API 获取实时天气预报和城市热度数据。
  - **评分计算：** 根据 4.5 节定义的城市综合评分算法，计算每个候选城市的
    `FinalScore`。
  - **结果排序与返回：** 将所有城市按 `FinalScore` 降序排列，返回 Top N
    个推荐城市。

**代码示例 (RecommendationService.java 核心片段):**

``` java
@Service
public class RecommendationService {

    @Autowired
    private CityRepository cityRepository;
    @Autowired
    private CityFeatureTagRepository cityFeatureTagRepository;
    @Autowired
    private UserInterestTagRepository userInterestTagRepository;
    @Autowired
    private WeatherService weatherService; // 假设有天气服务
    @Autowired
    private CityPopularityRepository cityPopularityRepository; // 假设有城市热度服务

    public List<RecommendationDto> getRecommendedCities(Long userId, Long departureCityId, List<String> userInterestTagNames, LocalDate travelDate) {
        // 1. 获取用户兴趣标签ID
        List<Long> userTagIds = userInterestTagRepository.findTagIdsByUserId(userId);
        
        // 2. 获取所有城市及其特征标签
        List<City> allCities = cityRepository.findAll();
        List<RecommendationDto> recommendations = new ArrayList<>();

        for (City city : allCities) {
            // 避免推荐出发城市
            if (city.getId().equals(departureCityId)) {
                continue;
            }

            // 获取城市特征标签
            List<Long> cityTagIds = cityFeatureTagRepository.findTagIdsByCityId(city.getId());

            // 计算偏好匹配度
            double preferenceScore = calculatePreferenceScore(userTagIds, cityTagIds);

            // 计算地理距离因子
            double distanceScore = calculateDistanceScore(departureCityId, city.getId()); // 假设HaversineDistanceUtil.calculateDistance

            // 获取天气舒适度因子
            double weatherScore = weatherService.getWeatherComfortScore(city.getId(), travelDate);

            // 获取城市热度因子
            double popularityScore = cityPopularityRepository.findByCityId(city.getId())
                                        .map(cp -> cp.getPopularityScore() / 100.0) // 归一化，假设原始分数0-100
                                        .orElse(0.0);

            // 综合评分
            double finalScore = 0.4 * preferenceScore + 0.3 * distanceScore + 0.2 * weatherScore + 0.1 * popularityScore;

            recommendations.add(new RecommendationDto(city.getId(), city.getName(), city.getProvince(), finalScore, city.getDescription()));
        }

        // 排序并返回Top N
        return recommendations.stream()
                .sorted(Comparator.comparingDouble(RecommendationDto::getScore).reversed())
                .limit(10) // 假设返回Top 10
                .collect(Collectors.toList());
    }

    private double calculatePreferenceScore(List<Long> userTagIds, List<Long> cityTagIds) {
        if (userTagIds.isEmpty() || cityTagIds.isEmpty()) return 0.0;
        Set<Long> intersection = new HashSet<>(userTagIds);
        intersection.retainAll(cityTagIds);
        Set<Long> union = new HashSet<>(userTagIds);
        union.addAll(cityTagIds);
        return (double) intersection.size() / union.size();
    }

    private double calculateDistanceScore(Long departureCityId, Long destinationCityId) {
        // 调用HaversineDistanceUtil或其他地图API计算距离
        // 这里简化为示例，实际需要从CityRepository获取经纬度
        City departureCity = cityRepository.findById(departureCityId).orElseThrow();
        City destinationCity = cityRepository.findById(destinationCityId).orElseThrow();
        double distance = HaversineDistanceUtil.calculateDistance(
            departureCity.getLatitude(), departureCity.getLongitude(),
            destinationCity.getLatitude(), destinationCity.getLongitude()
        );
        // 距离越小得分越高，这里假设最大距离为2000km进行归一化
        double maxDistance = 2000.0;
        return maxDistance / (distance + 1.0);
    }
}
```

### 5.2.3 第三方 API 集成

- **天气预报：** `QWeatherClient` 服务负责调用和风天气 API。
  - 使用 `RestTemplate` 或 `WebClient` 发送 HTTP 请求。
  - 返回结果通过 Valkey 缓存，键为 `weather:cityId:date`，有效期 \[1\]
    小时。
- **地图与位置服务：** `HaversineDistanceUtil` 提供了 Haversine
  公式实现的距离计算工具类。对于更复杂的地理位置解析，可集成高德/百度地图
  SDK。

## 5.3 性能优化实践

- **Valkey 缓存：**
  - **结果缓存：**
    热门城市列表、推荐算法的中间结果（如城市特征-标签匹配度）缓存到
    Valkey，减少重复计算。
  - **API 响应缓存：** 第三方天气 API
    的响应结果缓存，将天气查询响应时间从 \[200ms\] 降低至 \[5ms\]。
  - **缓存策略：** 合理设置缓存失效时间，采用 LRU 等淘汰策略。
- **数据库优化：**
  - **索引优化：** 确保所有查询涉及的字段（尤其是 JOIN、WHERE
    子句中的字段）都有合适的索引。
  - **慢查询优化：** 定期分析 MariaDB 慢查询日志，优化低效 SQL 语句。
  - **连接池优化：** 使用 HikariCP
    等高性能数据库连接池，合理配置连接数，提高数据库访问效率。
- **后端服务优化：**
  - **异步处理：**
    对于非核心、耗时操作（如日志记录、用户行为分析），采用 Spring 的
    `@Async` 注解或消息队列进行异步处理，避免阻塞主线程。
  - **JVM 调优：** 调整 JVM 内存参数（Xmx、Xms），优化垃圾回收策略。
  - **负载均衡：** 在多实例部署时，配置 Nginx
    或其他负载均衡器，将请求均匀分发到各个后端服务实例，提升并发处理能力。
